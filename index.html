01

Use AI tools by role

Choose the right tool for the job. Figma is your design source of truth, AI is for building, and the browser is where you check the result.

Prototype building

Codex, Cursor

Use when you want AI to create files, edit code, run the app, and fix visual or interaction issues.

Experience design and thinking

Claude, ChatGPT, Gemini

Use for flows, product logic, edge cases, UX copy, research, critique, and writing better prompts.

Interactive 3D design prototyping

Spline, Omma

Spline and Omma work together for quickly exploring 3D scenes, motion, spatial interfaces, product objects, and immersive experiences.

02

Basic concepts worth knowing

Concepts designers commonly encounter when asking AI to build working prototypes.

ViteA lightweight app starter that lets you preview React prototypes in the browser fast.
npmA tool for installing and running packages in JavaScript projects. Designers usually only need a few simple commands.
npm run devThe command to start a local preview server. It usually opens something like http://localhost:5173.
Root folderThe top-level folder of your project. AI uses this as the reference point for understanding files, assets, tokens, and instructions.
Design tokensColor, typography, spacing, and shadow values that AI should reuse — not invent on its own.
SKILLS.md / SKILL.mdA short instruction file that tells AI your team's prototyping standards and quality expectations.

03

Getting started with AI prototyping

A simple setup flow so you can start without being an engineer.

1

Install

Use Codex or Cursor for building. You'll also need Node.js to run the prototype locally.

2

Gather materials

Collect your Figma link, screenshots, design tokens, sample content, and product notes into one project folder.

3

Prompt

Tell AI your goal, the Figma frame you selected, the interactions you need, and what to keep simple.

4

Run

Ask AI to start the app with npm run dev, then open the local URL in your browser.

5

Review

Click through the prototype and compare it to Figma. Check spacing, typography, color, states, and mobile layout.

6

Refine

Give feedback in batches — visual accuracy first, then interactions, then polish.

04

Connecting Figma MCP

Figma MCP helps AI read design context more accurately — including selected frames, components, variables, and styles.

  • Use the remote Figma MCP server when possible.
  • Add https://mcp.figma.com/mcp to your AI tool's MCP settings.
  • Connect your Figma account and allow access.
  • Open your Figma file and select the frame you want to prototype.
  • Copy the link to the selected frame or layer.
  • Paste the link into an MCP-compatible tool like Codex, Cursor, or Claude Code.
  • Ask AI to analyze the design before writing any code.

The desktop MCP runs through the Figma desktop app and is mainly used in specific org or enterprise environments.

06

Recommended root folder structure

The root folder is the reference point for the prototype. A clear structure helps AI understand what to modify.

prototype-name/
  README.md
  package.json
  index.html
  src/
    App.jsx
    main.jsx
    styles.css
    components/
    data/
    assets/
  design/
    figma-link.md
    screenshots/
    tokens.json
  notes/
    prompts.md
    decisions.md
    SKILLS.md

src/ is where the working prototype code lives.

components/ stores reusable UI pieces like buttons, cards, and navigation.

data/ holds sample data that makes the prototype feel realistic.

design/ stores Figma links, screenshots, and design tokens.

notes/ stores prompts, decisions, and AI skill instructions.

08

Adding Spline or Omma 3D designs

Spline and Omma are useful for explaining products, objects, spaces, or motion in 3D — or exploring them interactively.

  • Prepare your interactive 3D design in Spline or Omma.
  • Get a shareable embed URL or export file.
  • Add it to the prototype using a viewer package, iframe, image, video, or 3D asset — whichever fits.
  • Keep the 3D area responsive and avoid making it too heavy.
  • Don't put important text only inside the 3D scene — also provide it in the HTML UI.
  • Prepare a static fallback image for slower devices.
Add this 3D design as the main interactive visual in the prototype.
Keep it responsive and include a fallback image.
3D design URL: [Paste Spline or Omma URL here]

09

SKILLS.md for more accurate AI output

SKILLS.md is an instruction file that tells AI how your design team works, what quality looks like, and the rules for building prototypes.

What to include

  • Audience and prototype purpose
  • Design token usage rules
  • Component usage rules
  • Responsive layout standards
  • Interaction and motion standards
  • Accessibility standards
  • What AI should avoid

Where to put it

Save it near your prototype notes — for example at notes/SKILLS.md. Some AI tools use the singular SKILL.md, so match the filename your tool expects.

Simple SKILLS.md template

# AI Prototyping Skills for Product Designers

## Role
Act as a senior product designer and frontend prototyper.

## Goal
Build accurate, clickable prototypes based on Figma designs.

## Design rules
- Use the provided design tokens exactly.
- Match spacing, typography, color, radius, and component states.
- Use existing components before creating new ones.
- Make it responsive for both desktop and mobile.

## Interaction rules
- Add realistic hover, focus, selected, loading, empty, and error states.
- Keep flows simple and testable.
- Do not create new screens unless required.

## Output rules
- Keep the code easy to edit.
- Use realistic sample data.
- Explain what is clickable, static, and placeholder.
- Share assumptions before making large changes.

## What to avoid
- Arbitrary colors not in the tokens.
- Decorative UI not in the design.
- Structure that is more complex than the prototype needs.

Pushing code to GitHub

The most basic flow for saving and sharing AI-prototyping code on GitHub.

00

What to know first

  • GitHub is a service for storing and sharing code online.
  • Repo is a project folder inside GitHub. If a Figma file is the source of truth for design, a repo is the source of truth for code.
  • Local project is the prototype folder on your computer. Example: AI Prototyping Guide
  • Terminal is the app where you type commands. On Mac use Terminal; in Cursor use the Terminal panel at the bottom.
  • remote is the online GitHub repo address linked to your local folder.
  • origin is the nickname for that remote. The first GitHub repo is usually called origin.
  • main is the default branch name. Think of a branch as the main line of your work history.
01

Create a GitHub repo

Do this step in a browser on the GitHub website.

  1. Log in to GitHub.
  2. Click the + button in the top right and select New repository.
  3. Enter a repository name. Example: ai-checkout-prototype
  4. Choose visibility: Private or Public.
  5. If you already have local code, skip adding README, gitignore, and license for now — it's simpler.
  6. Click Create repository.
  7. Copy the repo URL shown after creation. Example: https://github.com/USERNAME/REPO-NAME.git
02

Where to type commands

Commands must be typed from inside the prototype project folder.

  1. Open the prototype folder in Codex or Cursor.
  2. Open the terminal. In Cursor it's usually the Terminal panel at the bottom.
  3. Confirm the terminal is pointing at your project folder.
pwd

pwd shows which folder the terminal is currently in.

03

Connect your local project to GitHub

Type these commands in the terminal one line at a time. Replace USERNAME and REPO-NAME with your GitHub details.

git init
git add .
git commit -m “Initial AI prototype”
git branch -M main
git remote add origin https://github.com/USERNAME/REPO-NAME.git
git remote -v

When git remote -v shows the GitHub URL, the connection is set. If a remote already exists, use git remote set-url origin [new GitHub URL].

04

Push your AI prototype code

Push uploads the saved version from your computer to the GitHub repo. Type this in the terminal.

git push -u origin main

For future updates, just repeat this loop.

git status
git add .
git commit -m “Update prototype”
git push origin main
05

What each command does

  • pwd shows the folder the terminal is currently open in.
  • git init turns the current folder into a Git-tracked project.
  • git status shows which files have changed.
  • git add . stages changed files ready to commit.
  • git commit saves a snapshot of the current version.
  • git remote add origin ... links your local folder to the GitHub repo.
  • git push uploads the saved version to GitHub.
06

Checkpoint for designers

  • Type commands in the terminal, not on the GitHub website.
  • The terminal must be open inside the prototype project folder.
  • Never push files containing API keys, passwords, tokens, or personal data.
  • When asking Codex or Cursor, say something like “Check the changes, commit, and push to GitHub.”

Prepare this AI prototype project so it can be pushed to GitHub.

GitHub repo URL:

- Check the current changes.

11

Useful tips

Small habits that improve the quality of your AI prototypes.

  • Build one core user journey before expanding the prototype.
  • Give AI the Figma link, screenshots, tokens, and product notes together.
  • Request small changes instead of asking AI to rebuild everything at once.
  • Use realistic sample data so the UI can be properly judged.
  • Save prompts that worked well in notes/prompts.md.
  • Document what is clickable, static, fake data, unfinished, or intentionally simplified.
