01

AI 도구를 역할별로 사용하기

도구를 목적에 맞게 고르세요. Figma는 기준 디자인, AI는 제작 도구, 브라우저는 실제 작동 여부를 확인하는 공간입니다.

프로토타입 제작

Codex, Cursor

AI가 파일을 만들고, 코드를 수정하고, 앱을 실행하고, 시각적 오류나 인터랙션 문제를 고치게 할 때 사용합니다.

경험 설계와 사고 정리

Claude, ChatGPT, Gemini

플로우, 제품 로직, 엣지 케이스, UX 문구, 리서치, 크리틱, 더 좋은 프롬프트를 정리할 때 사용합니다.

인터랙티브 3D 디자인 프로토타이핑

Spline, Omma

Spline과 Omma는 3D 씬, 모션, 공간형 인터페이스, 제품 오브젝트, 몰입형 경험을 빠르게 탐색할 때 함께 사용할 수 있습니다.

02

알아두면 좋은 기본 개념

AI에게 작동하는 프로토타입을 만들게 할 때 디자이너가 자주 마주치는 개념입니다.

ViteReact 프로토타입을 브라우저에서 빠르게 미리 볼 수 있게 해주는 가벼운 앱 시작 도구입니다.
npmJavaScript 프로젝트에 필요한 패키지를 설치하고 실행하는 도구입니다. 디자이너는 보통 간단한 명령어로만 사용합니다.
npm run dev로컬 미리보기 서버를 실행하는 명령어입니다. 보통 http://localhost:5173 같은 주소가 열립니다.
Root folder프로젝트의 가장 상위 폴더입니다. AI는 이 폴더를 기준으로 파일, 에셋, 토큰, 지시사항을 이해합니다.
Design tokensAI가 임의로 색상이나 간격을 만들지 않고 재사용해야 하는 컬러, 타이포, 간격, 그림자 값입니다.
SKILLS.md / SKILL.mdAI에게 우리 팀의 프로토타입 제작 기준과 품질 기준을 알려주는 짧은 지시문 파일입니다.

03

AI 프로토타이핑 시작하기

엔지니어가 되지 않아도 시작할 수 있도록, 준비 과정을 단순하게 나눈 흐름입니다.

1

설치하기

제작에는 Codex나 Cursor를 사용합니다. 프로토타입을 로컬에서 실행하려면 Node.js도 필요합니다.

2

자료 모으기

Figma 링크, 스크린샷, 디자인 토큰, 샘플 콘텐츠, 제품 메모를 하나의 프로젝트 폴더에 모읍니다.

3

요청하기

목표, 선택한 Figma 프레임, 필요한 인터랙션, 단순하게 유지할 부분을 AI에게 알려줍니다.

4

실행하기

AI에게 npm run dev로 앱을 실행하게 하고, 로컬 URL을 브라우저에서 엽니다.

5

리뷰하기

프로토타입을 직접 클릭해보고 Figma와 비교합니다. 간격, 타이포, 컬러, 상태, 모바일 레이아웃을 확인합니다.

6

다듬기

피드백은 한 번에 몰아서 주지 말고, 시각적 정확도, 인터랙션, 마감 순서로 나눠 요청합니다.

04

Figma MCP 연결하기

Figma MCP는 AI가 선택한 프레임, 컴포넌트, 변수, 스타일 같은 디자인 맥락을 더 정확히 읽게 도와줍니다.

  • 가능하면 원격 Figma MCP 서버를 사용합니다.
  • AI 도구의 MCP 설정에 https://mcp.figma.com/mcp를 추가합니다.
  • Figma 계정을 연결하고 접근 권한을 허용합니다.
  • Figma 파일을 열고 프로토타입으로 만들 프레임을 선택합니다.
  • 선택한 프레임이나 레이어 링크를 복사합니다.
  • Codex, Cursor, Claude Code처럼 MCP를 지원하는 도구에 링크를 붙여넣습니다.
  • 코드를 만들기 전에 AI에게 디자인을 먼저 분석해달라고 요청합니다.

데스크톱 MCP는 Figma 데스크톱 앱을 통해 실행되며, 주로 특정 조직이나 엔터프라이즈 환경에서 사용합니다.

05

AI 프로토타이핑 워크플로우

Figma 디자인을 클릭 가능한 브라우저 프로토타입으로 옮길 때 반복해서 사용할 수 있는 흐름입니다.

01

준비

Figma 프레임을 정리하고, 레이어 이름을 다듬고, 토큰과 핵심 플로우를 모읍니다.

02

프롬프트

Figma 링크, 목표, 제약사항, 토큰, 필요한 상태를 AI에게 전달합니다.

03

제작

AI가 단순한 컴포넌트와 현실적인 샘플 데이터로 첫 버전을 만들게 합니다.

04

미리보기

앱을 로컬에서 실행하고 데스크톱과 모바일 크기에서 브라우저로 확인합니다.

05

수정

시각적 정확도, 인터랙션 상태, 엣지 케이스, 반응형 레이아웃을 다듬습니다.

06

공유

클릭 가능한 부분, 정적인 부분, 가짜 데이터, 미완성 영역, 리뷰 가능한 범위를 기록합니다.

루트 폴더는 프로토타입의 기준 위치입니다. 구조가 정리되어 있으면 AI가 무엇을 수정해야 하는지 더 잘 이해합니다.

src/는 실제 프로토타입 코드가 들어가는 곳입니다.

components/는 버튼, 카드, 내비게이션처럼 재사용하는 UI 조각을 저장합니다.

data/는 프로토타입을 현실적으로 보이게 하는 샘플 데이터를 저장합니다.

design/은 Figma 링크, 스크린샷, 디자인 토큰을 저장합니다.

notes/는 프롬프트, 결정사항, AI 스킬 지시문을 저장합니다.

AI 결과를 더 정확하게 만드는 SKILLS.md

SKILLS.md는 AI에게 우리 디자인 팀의 작업 방식, 품질 기준, 프로토타입 제작 규칙을 알려주는 지시문입니다.

포함하면 좋은 내용

  • 사용자와 프로토타입 목적
  • 디자인 토큰 사용 규칙
  • 컴포넌트 사용 규칙
  • 반응형 레이아웃 기준
  • 인터랙션과 모션 기준
  • 접근성 기준
  • AI가 피해야 할 것

어디에 두면 좋을까?

프로토타입 메모 근처에 저장하세요. 예를 들면 notes/SKILLS.md처럼 둘 수 있습니다. 일부 AI 도구는 단수 파일명인 SKILL.md를 사용하므로, 사용하는 도구가 기대하는 파일명에 맞추면 됩니다.

간단한 SKILLS.md 템플릿

# 프로덕트 디자이너를 위한 AI 프로토타이핑 스킬

## 역할
시니어 프로덕트 디자이너이자 프론트엔드 프로토타이퍼처럼 행동해줘.

## 목표
Figma 디자인을 기반으로 정확하고 클릭 가능한 프로토타입을 만들어줘.

## 디자인 규칙
- 제공된 디자인 토큰을 정확히 사용해줘.
- 간격, 타이포그래피, 컬러, radius, 컴포넌트 상태를 맞춰줘.
- 새 컴포넌트를 만들기 전에 기존 컴포넌트를 우선 사용해줘.
- 데스크톱과 모바일 모두 반응형으로 만들어줘.

## 인터랙션 규칙
- 현실적인 hover, focus, selected, loading, empty, error 상태를 추가해줘.
- 플로우는 단순하고 테스트 가능하게 유지해줘.
- 필요하지 않은 화면은 새로 만들지 마.

## 결과물 규칙
- 코드는 쉽게 수정할 수 있게 유지해줘.
- 현실적인 샘플 데이터를 사용해줘.
- 클릭 가능한 것, 정적인 것, placeholder인 것을 설명해줘.
- 큰 변경을 하기 전에는 가정을 먼저 알려줘.

## 피해야 할 것
- 토큰에 없는 임의의 컬러 사용.
- 디자인에 없는 장식적인 UI 추가.
- 프로토타입에 비해 과하게 복잡한 구조.

10

GitHub에 코드 올리기

AI 프로토타이핑으로 만든 코드를 GitHub에 저장하고 공유하는 가장 기본적인 흐름입니다.

00

먼저 알아야 할 것

  • GitHub는 코드를 온라인에 저장하고 공유하는 서비스입니다.
  • Repo는 GitHub 안에 있는 프로젝트 폴더입니다. Figma 파일 하나가 디자인의 기준이라면, repo는 코드의 기준입니다.
  • 로컬 프로젝트는 내 컴퓨터에 있는 프로토타입 폴더입니다. 예: AI Prototyping Guide
  • 터미널은 명령어를 입력하는 앱입니다. Mac에서는 Terminal, Cursor에서는 하단의 Terminal 패널을 사용합니다.
  • remote는 내 컴퓨터 폴더와 연결된 온라인 GitHub repo 주소입니다.
  • origin은 remote에 붙이는 별명입니다. 보통 첫 GitHub repo를 origin이라고 부릅니다.
  • main은 기본 브랜치 이름입니다. 브랜치는 작업 흐름의 줄기라고 생각하면 됩니다.
01

GitHub repo 생성

이 단계는 브라우저에서 GitHub 웹사이트를 열고 진행합니다.

  1. GitHub에 로그인합니다.
  2. 오른쪽 위 + 버튼에서 New repository를 선택합니다.
  3. Repository name을 입력합니다. 예: ai-checkout-prototype
  4. 공개 범위를 선택합니다: Private 또는 Public.
  5. 이미 로컬에 코드가 있다면 README, gitignore, license는 일단 추가하지 않는 편이 쉽습니다.
  6. Create repository를 누릅니다.
  7. 생성 후 보이는 repo URL을 복사합니다. 예: https://github.com/USERNAME/REPO-NAME.git
02

명령어를 어디에 입력할까?

명령어는 반드시 프로토타입 프로젝트 폴더 안에서 입력해야 합니다.

  1. Codex나 Cursor에서 프로토타입 폴더를 엽니다.
  2. 터미널을 엽니다. Cursor는 보통 하단 패널의 Terminal입니다.
  3. 터미널 위치가 프로젝트 폴더인지 확인합니다.
pwd

pwd는 “지금 터미널이 어느 폴더를 보고 있는지” 확인하는 명령어입니다.

03

로컬 프로젝트와 GitHub 연결

이 명령어들은 터미널에 한 줄씩 입력합니다. USERNAME과 REPO-NAME은 본인의 GitHub 정보로 바꿉니다.

git init
git add .
git commit -m "Initial AI prototype"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO-NAME.git
git remote -v

git remote -v를 입력했을 때 GitHub 주소가 보이면 연결된 것입니다. 이미 remote가 있다면 git remote set-url origin [새 GitHub URL]을 사용합니다.

04

AI 프로토타입 코드 push

Push는 내 컴퓨터에 저장한 버전을 GitHub repo로 업로드하는 동작입니다. 이 명령어도 터미널에 입력합니다.

git push -u origin main

다음부터 업데이트할 때는 이 흐름만 반복하면 됩니다.

git status
git add .
git commit -m "Update prototype"
git push origin main
05

명령어가 하는 일

  • pwd는 지금 터미널이 열려 있는 폴더 위치를 보여줍니다.
  • git init은 현재 폴더를 Git이 추적할 수 있는 프로젝트로 만듭니다.
  • git status는 현재 변경된 파일을 확인하는 명령어입니다.
  • git add .는 변경된 파일을 커밋 준비 상태로 올립니다.
  • git commit은 현재 버전을 저장하는 스냅샷입니다.
  • git remote add origin ...은 내 컴퓨터 폴더와 GitHub repo를 연결합니다.
  • git push는 저장한 버전을 GitHub에 업로드합니다.
06

디자이너를 위한 체크포인트

  • 명령어는 GitHub 웹사이트가 아니라 터미널에 입력합니다.
  • 터미널은 프로토타입 프로젝트 폴더 안에서 열려 있어야 합니다.
  • API key, 비밀번호, 토큰, 개인 정보가 들어간 파일은 절대 push하지 않습니다.
  • Codex나 Cursor에 요청할 때는 “변경사항 확인 후 commit하고 GitHub에 push해줘”처럼 말하면 됩니다.
